# ONHARU 2.1 오늘 변경분 리팩토링 감사

작성일: 2026-08-22  
범위: 연도·기념일 입력, 백업 복원, D-Day 카드, 투명도 저장, 동기화 상태, 혼합 DPI 위치, 공통 입력 디자인

## 결론

오늘 변경분은 기존 책임 파일 안에 배치되어 있으며 대규모 재분리는 필요하지 않다. 기능 동작을 바꾸지 않는 세 가지 정리를 수행했고, 빌드와 13개 품질 게이트를 통과했다.

## 이번에 수행한 정리

1. Google 상태 타이머 단일화
   - 이전 구현은 상태를 표시할 때마다 지역 `DispatcherTimer`를 만들었다.
   - 이전 타이머가 뒤늦게 실행되어 새 `동기화 중` 또는 `동기화 완료` 문구를 숨길 수 있었다.
   - `MainWindow.googleStatusTimer` 하나만 유지하고 새 상태 표시 전에 이전 타이머를 중단한다.

2. 백업 경로 마이그레이션 1회화
   - `%LOCALAPPDATA%\OnharuV3\backups`에서 `%LOCALAPPDATA%\Onharu\backups`로 복사하는 검사를 백업 조회·저장마다 반복할 필요가 없었다.
   - 프로세스당 한 번만 실행하도록 잠금과 완료 플래그를 추가했다.
   - 기존 파일은 삭제하지 않고 새 위치에 없는 파일만 복사하는 안전 정책을 유지한다.

3. 빈 예외 처리 제거
   - 백업 폴더 열기 실패를 무시하던 `catch { }`를 개인정보 없는 오류 로그 기록으로 교체했다.

## 현재 분리 상태 판정

- `MainWindow.*.cs`: 오늘 변경은 Settings, Google, Layout, Anniversary, Placement 책임에 맞게 들어가 있다.
- `BackupWindow.cs` 112줄, `AnniversaryWindow.cs` 144줄, `MonthJumpWindow.cs` 108줄은 독립 창으로 적절하다.
- `UiRound.cs`에 공통 TextBox·Button 템플릿을 둔 것은 디자인 중복을 줄이는 올바른 경계다.
- `LocalStorage.cs`는 데이터 저장과 백업 경로 마이그레이션을 함께 관리하므로 현재 변경은 책임 범위 안이다.
- `AddItemWindow.cs`는 800줄대로 크지만 대부분 절차적 UI 구성이다. 오늘 변경만을 이유로 급하게 partial로 나누면 동등성 위험이 더 크므로 2.1 배포 직전에는 유지한다.

## 배포 후 별도 리팩토링 후보

- `AddItemWindow.cs`: 날짜·시간, 반복, 알림, 저장 검증 섹션 빌더 분리.
- `SettingsWindow.cs`: 표시, 색상, Google, 데이터 관리 섹션 빌더 분리.
- 데이터 작업의 여러 bool 플래그를 단일 작업 enum으로 교체.

이 세 항목은 기능 동등성 검증 패키지를 먼저 만든 뒤 진행하며 2.1 최종 배포를 막는 항목은 아니다.

# ONHARU 2.2 스킨 시스템

## 목표

ONHARU 2.2는 기능과 Explorer 레이어 동작을 유지한 채 외형만 교체할 수 있어야 한다. 스킨은 화면별 코드를 복제하지 않고, 같은 렌더러가 의미 기반 색상 역할을 읽는 방식으로 적용한다.

## 현재 제공 스킨

- `classic`: 기존 ONHARU 파스텔 디자인
- `dark`: 어두운 배경과 밝은 글자를 사용하는 블랙 디자인
- 지원 스킨은 `classic`(파스텔)과 `dark`(블랙) 두 개뿐이다. 과거 시험용 `colorful` 값은 `classic`으로 정규화하며 별도 팔레트 코드는 유지하지 않는다.

설정에는 사용자용 이름을 표시하지만 저장 파일에는 위의 언어 독립 ID만 기록한다. 알 수 없는 값은 항상 `classic`으로 복구한다.

## 구조

- `App/OnharuTheme.cs`: 스킨 ID, 팔레트, 의미 기반 색상 역할의 유일한 원본
- `App/CategoryColorSystem.cs`: 사용자 기준색을 스킨별 일정 배경·글자·테두리로 변환하고 최소 4.5:1 대비를 보장하는 공통 모듈
- `App/MainWindow.Theme.cs`: 현재 팔레트를 브러시에 적용하고 일정·체크박스 표현을 선택
- `App/MainWindow.Layout.cs`: 메인 외곽, 달력, 사이드바와 공통 버튼
- `App/MainWindow.Calendar.cs`: 날짜 셀, 요일, 일정 막대
- `App/MainWindow.Detail.cs`: 오른쪽 상세 일정 카드
- `App/SettingsWindow.cs`: 스킨 선택 UI
- `App/PlannerSettings.cs`, `App/LocalStorage.cs`: `ThemeId` 저장과 안전한 마이그레이션

## 의미 기반 색상 역할

`Shell`, `Calendar`, `Sidebar`, `CardBorder`, `Grid`, `Text`, `Heading`, `Muted`, `Accent`, `AccentSoft`, `AccentBorder`, `Button`, `Disabled`, `Weekday`를 사용한다. 새 UI에서 `#RRGGBB`를 직접 추가하기 전에 이 역할로 표현할 수 있는지 먼저 확인한다.

카테고리·사용자 지정 색상·중요한 날 색상은 스킨 팔레트와 별개의 사용자 데이터다. 전역 색상 치환으로 이 값을 바꾸면 안 된다.

## 안정성 경계

- 완성된 `Onharu_v2.1`을 기능·디자인·배치의 기준선으로 사용한다. 2.2 변경 전후에 대응 파일과 실제 화면을 비교한다.
- 스킨으로 바뀌는 항목은 의미 색상과 명시적으로 승인된 시각 표현뿐이다. 2.1의 크기, 간격, 정렬, 클릭 영역은 별도 요청 없이 바꾸지 않는다.
- hover 기본 규칙은 스킨과 무관하게 동일하다. 일반 버튼·날짜 제목은 손 모양 커서만 바꾸고 배경·글자 색을 반전하지 않는다. 선택 상태, 슬라이딩 토글의 활성 항목, 메뉴·목록 탐색, 위험 경고처럼 의미 전달이 필요한 곳만 색상 강조를 사용한다.
- `Icon`은 공통 의미 역할이다. `classic`은 검정 계열, `dark`는 흰색을 사용하며 아이콘 버튼의 Padding은 0, 콘텐츠 정렬은 중앙으로 고정한다.
- 주요 헤더 아이콘은 17px 벡터 뷰박스와 약 1.8px 획을 기준으로 한다. `« ‹ › »`, 검색, 시간표, 일기처럼 작은 글꼴 기호에서 식별력이 떨어지는 아이콘은 문자 대신 벡터 경로를 사용한다.

## 스킨별 일정 색상 규칙

- `파스텔`: 기준색에 흰색 80%를 혼합한 배경과, 같은 계열에서 4.5:1 대비를 만족하는 가장 부드러운 진한 글자를 사용한다. 이 계산은 메인 달력·설정 편집 카드·오른쪽 상세 카드에 공통 적용한다.
- `블랙`: 어두운 달력 면 위에 선명한 일정 배경을 사용하고, 배경에 따라 같은 계열의 밝거나 진한 글자를 자동 선택한다.
- 두 스킨 모두 최종 글자 대비율 4.5:1을 만족해야 하며, 동계열 후보가 부족하면 `#111827`·흰색을 거쳐 검정·흰색 중 대비가 높은 쪽으로 안전하게 대체한다.
- 오른쪽 상세 열의 배경·글자는 `CategoryColorSystem.Detail*` 별칭을 통해 메인 일정의 `Background`·`Foreground` 결과를 그대로 사용한다. 체크박스만 조작 상태의 가시성을 위해 `CheckBoxBackground`의 한 단계 진한 색을 사용한다.
- `OnharuColorPresets`: 5개 추천 프리셋 이름·기준색과 최초 카테고리 색상을 소유한다. 설정 화면은 배열을 직접 정의하지 않는다.
- `OnharuStateColors`: 오른쪽 범위 탭과 중요한 날 버튼의 선택·미선택 상태색을 소유한다. 화면 코드는 반환된 배경·글자·테두리만 적용한다.
- 메인 헤더의 `파스텔·블랙` 빠른 전환은 항상 표시한다. 사용자가 숨기는 별도 설정은 제공하지 않으며 설정창 맨 위의 `디자인 스킨`과 같은 `ThemeId`를 사용한다.
- `<프리셋명> 변경` 버튼은 선택한 프리셋 대표색의 파스텔 배경과 동계열 진한 글자를 사용한다.
- 설정 색상 영역은 `디자인 스킨 → 추천 프리셋 → RGB·프리셋 변경·내 설정 저장·추천색 초기화·색상 교환 → 색상 카드` 순서를 사용하고, 추천 조합부터 색상 카드까지 하나의 테두리로 묶는다. 추천색 초기화는 기본 다섯 프리셋만 복원하고 내 설정은 보존한다.
- 색상 선택 수에는 제한이 없다. 정확히 두 항목을 선택했을 때만 교환할 수 있고 교환은 화면 값만 바꾼다. `내 설정으로 저장`은 하나 이상 선택했을 때 체크된 항목만 내 설정 슬롯에 갱신한다. `<프리셋명> 변경`은 현재 전체 색상을 해당 프리셋에 저장한다.
- 파스텔 디자인 선택 카드는 현재 선택한 프리셋의 대표색을 파스텔 배경과 동계열 진한 글자로 변환해 보여준다.
- 로컬 색상 카드는 업무, 개인, 야구, D-Day, 기념일, 휴일을 동일하게 제공한다. Google 기본색은 별도 읽기 전용 선택으로 유지한다.
- 슬라이딩 버튼은 12.5px SemiBold, 좌우 2px Padding과 실제 글자 측정값 기반 최소 폭을 사용한다. 정확한 헤더 치수와 정렬선은 `../Design/MAIN_HEADER_UI_STANDARD.md`를 따른다. 브랜드명과 메인 연·월 제목은 테마 역할색이 아니라 공통 ONHARU 그라데이션을 사용한다.
- Explorer 훅, 공유 프레임, 입력 좌표, 이동·고정 전환 코드는 스킨 때문에 수정하지 않는다.
- 렌더링 결과만 달라지고 같은 프레임 게시 경로를 사용한다.
- 저장된 `ThemeId`가 없거나 손상되면 `classic`으로 시작한다.
- 스킨별 MainWindow 복제, 대형 컨트롤 팩토리, 런타임 플러그인 로더는 만들지 않는다.

## 검증

`App/theme-check.ps1`이 두 팔레트의 필수 역할, 색상 형식, 서로 다른 외곽색, 기본값과 fallback을 검사한다. 모든 기본 프리셋 색을 두 스킨으로 변환한 뒤 배경·글자 대비율이 4.5:1 이상인지도 실행 코드로 검증한다. 전체 검증은 저장소 루트에서 다음 명령으로 실행한다.

```powershell
.\check-v22.ps1 -Build
```

## 다음 확장 규칙

메인 달력에서 검증된 뒤 공통 팝업과 기능별 창을 순차 적용한다. 각 화면은 먼저 2.1 대응 소스의 치수와 배치를 확인한다. 새 스킨을 추가할 때는 팔레트 1개와 설정 선택지만 추가하고 기능 코드나 Explorer 레이어를 복제하지 않는다.

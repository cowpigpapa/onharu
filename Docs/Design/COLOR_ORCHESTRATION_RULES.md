# ONHARU 색상 오케스트레이션 원칙

이 문서는 색상을 추천·적용하는 오케스트레이터의 실행 규칙이다. 실제 HEX와 대비 계산은 `COLOR_PALETTE_STANDARD.md`와 `CategoryColorSystem`을 단일 기준으로 사용한다.

## 1. 목표와 사용량

- 일정 출처와 상태는 빠르게 구분하되 여러 강조색이 서로 경쟁하지 않게 한다.
- 중립면 70~80%, 카테고리색 15~25%, 선택·오늘·경고 강조색 5% 이하를 기준으로 한다.
- 프리셋 대표색은 반복 장식이 아니다. 헤더·선택 상태·일정 막대가 동시에 대표색이면 하나만 남기고 나머지는 중립색이나 옅은 면으로 낮춘다.
- 한 컴포넌트에서는 배경·테두리·아이콘·글씨 중 최대 두 요소만 유채색을 쓴다.

## 2. 프리셋 운용

- 다섯 프리셋은 UI 테마 다섯 개가 아니라 카테고리 구분용 색 묶음이다.
- 대표색은 업무일정과 핵심 선택 상태, 두 번째 색은 개인일정과 보조 구분에 우선한다.
- 나머지 색은 Google 캘린더와 특수 일정이 실제로 있을 때만 순서대로 쓴다. 빈 카테고리를 위해 장식을 추가하지 않는다.
- 야구 `#38A169`, 휴일 `#DC2626`은 의미색으로 고정한다. D-Day와 기념일은 프리셋 지정색만 쓴다.
- 인접한 두 색이 비슷하면 RGB를 조금 바꾸지 말고 배열 내 다른 색상 계열로 순서를 교체한다.

## 3. 1번 파스텔

- 일정 배경은 기준색과 흰색을 20:80으로 혼합한다.
- 글씨는 같은 색상의 진한 톤을 우선하되 4.5:1 미달이면 안전한 진회색으로 바꾼다.
- 큰 면에는 원색을 쓰지 않는다. 원색은 체크 면, 작은 아이콘, 가는 테두리에만 허용한다.
- 파스텔 배경과 유채색 테두리를 함께 썼다면 본문 아이콘은 중립색으로 둔다.
- 연속 카드의 구분은 채도보다 여백·라벨·정렬로 해결한다.

## 4. 2번 블랙

- 기본 배경은 `#121212`, 표면은 `#1A1A1A` 계열을 유지한다.
- 기준색을 네온처럼 띄우지 않는다. `CategoryColorSystem`이 배경을 어둡혀 흰 글씨 4.5:1을 확보한 결과만 쓴다.
- 네온 효과, 발광 그림자, 고채도 외곽선 중복은 금지한다. 상태는 면 또는 1px 테두리 하나로 표현한다.
- 밝은 노랑·라임·시안은 원색 보존보다 읽기 쉬운 글씨를 우선해 배경을 자동으로 어둡힌다.
- 본문은 `#F8FAFC`, 보조 글씨는 `#CBD5E1`을 기본으로 하고 순백색은 작은 일정 글씨와 핵심 선택 상태에 제한한다.

## 5. 사용자 지정색 안전 규칙

- 저장된 글씨색은 선호값이지 최종 렌더링 명령이 아니다.
- 실제 배경과 선호 글씨의 대비가 4.5:1 이상이면 유지하고, 미달이면 검정·흰색 중 대비가 높은 색으로 자동 보정한다.
- 설정 미리보기, 메인 달력, 오른쪽 상세 카드가 같은 결과를 보여야 한다.
- 흰 배경+흰 글씨, 검정 배경+검정 글씨, 투명 배경 위 가변 글씨는 금지한다.

## 6. 오케스트레이터 결정 순서

1. 정보색인지 장식색인지 판단한다. 장식이면 중립색을 우선한다.
2. 정보색이면 고정 의미색을 확인하고, 아니면 현재 프리셋 배열 순서를 쓴다.
3. 스킨에 맞춰 `CategoryColorSystem`으로 배경·글씨·테두리를 계산한다.
4. 실제 배경과 글씨 대비 4.5:1 이상을 검증한다.
5. 인접 요소가 경쟁하면 채도를 높이지 말고 한쪽을 중립색으로 낮춘다.
6. 파스텔·블랙과 설정 미리보기·달력·상세 카드를 함께 확인한다.

## 7. 금지

- 화면마다 별도 HEX 또는 글씨색 계산 추가
- 대표색을 헤더·버튼·카드·아이콘에 동시에 반복
- 블랙 스킨에서 네온색과 발광 효과로 구분
- 대비 검증 없이 사용자 글씨색을 그대로 출력
- 중복 회피를 위한 난수색 또는 미세 RGB 변형

# ONHARU 색상 오케스트레이션 원칙

이 문서는 색상을 추천·적용하는 오케스트레이터의 실행 규칙이다. 실제 HEX와 대비 계산은 `COLOR_PALETTE_STANDARD.md`와 `CategoryColorSystem`을 단일 기준으로 사용한다.

밝고 낮은 채도의 생산성 UI가 필요한 경우 `SOFT_WORKSPACE_COLOR_REFERENCE.md`의 톤과 `내설정` 기준 배열을 사용한다.

## 1. 목표와 사용량

- 일정 출처와 상태는 빠르게 구분하되 여러 강조색이 서로 경쟁하지 않게 한다.
- 중립면 70~80%, 카테고리색 15~25%, 선택·오늘·경고 강조색 5% 이하를 기준으로 한다.
- 프리셋은 특정 대표색 하나의 변형이 아니라 서로 구분되는 여러 색을 밝은 톤으로 조합한 묶음이다.
- 선택 버튼 등에 필요한 인터페이스 강조색은 내부적으로 하나를 사용하되, 그 색이 프리셋 전체의 정체성이나 카테고리 배치 순서를 지배하지 않는다.
- 메인 창 제어, 보기·스킨·위치·정렬 스위치와 투명도 조절은 프리셋 대표색에서 분리한 중립 인터페이스 색을 사용한다.
- 최소화·최대화·닫기는 기본 상태에서 같은 중립 배경·글씨·테두리를 사용한다. 종료 위험색은 확인 단계에서만 강조한다.
- 한 컴포넌트에서는 배경·테두리·아이콘·글씨 중 최대 두 요소만 유채색을 쓴다.

## 2. 프리셋 운용

- 세 프리셋은 `맑고 선명한 조합·차분한 중간톤·밝고 산뜻한 조합`이다. 이름은 대표색이 아니라 전체 톤을 뜻한다.
- 한 프리셋 안에는 블루·핑크·그린·바이올렛·오렌지·옐로 계열을 고르게 배치한다. 프리셋 이름과 같은 색만 반복하지 않는다.
- 나머지 색은 Google 캘린더와 특수 일정이 실제로 있을 때만 순서대로 쓴다. 빈 카테고리를 위해 장식을 추가하지 않는다.
- 모든 추천 조합은 분홍·오렌지·골드·그린·블루·라벤더를 포함하고, 시안·틸·인디고·코랄·라임·브라운을 더한 서로 다른 12색으로 구성한다.
- 인접한 두 색이 비슷하면 RGB를 조금 바꾸지 말고 배열 내 다른 색상 계열로 순서를 교체한다.
- `시작할 때 색상 무작위 배치`를 켠 경우에만 선택한 12색의 카테고리 배치를 시작할 때 섞는다. 끄면 사용자가 마지막으로 저장한 배치를 그대로 유지한다.

## 3. 파스텔

- 추천 팔레트의 배경과 글씨는 작성 단계에서 한 쌍으로 확정하고 실행 중 다시 계산하거나 변경하지 않는다.
- 글씨는 같은 색상의 진한 톤을 기본으로 하며, 확정 전 모든 조합이 4.5:1 이상인지 검사한다.
- 메인 달력과 오른쪽 상세 카드는 같은 기준색, 같은 혼합률, 같은 글씨 계산 결과를 그대로 사용한다.
- 오른쪽 체크박스는 같은 계열에서 카드보다 한 단계 선명하게 만들되 어둡게 만들지 않는다.
- 낮은 명도로 탁하고 어둡게 느껴지는 파스텔 결과는 추천 조합에서 제외한다.
- 큰 면에는 원색을 쓰지 않는다. 원색은 체크 면, 작은 아이콘, 가는 테두리에만 허용한다.
- 파스텔 배경과 유채색 테두리를 함께 썼다면 본문 아이콘은 중립색으로 둔다.
- 연속 카드의 구분은 채도보다 여백·라벨·정렬로 해결한다.

## 4. 2번 블랙

- 기본 배경은 `#121212`, 표면은 `#1A1A1A` 계열을 유지한다.
- 기준색을 네온처럼 띄우지 않는다. `CategoryColorSystem`이 배경을 어둡혀 흰 글씨 4.5:1을 확보한 결과만 쓴다.
- 네온 효과, 발광 그림자, 고채도 외곽선 중복은 금지한다. 상태는 면 또는 1px 테두리 하나로 표현한다.
- 밝은 노랑·라임·시안은 원색 보존보다 읽기 쉬운 글씨를 우선해 배경을 자동으로 어둡힌다.
- 본문은 `#F8FAFC`, 보조 글씨는 `#CBD5E1`을 기본으로 하고 순백색은 작은 일정 글씨와 핵심 선택 상태에 제한한다.

## 5. 사용자 지정색 안전 규칙

- 추천 프리셋에 저장된 배경·글씨 쌍은 최종 렌더링 명령이다.
- 사용자가 임의 HEX를 입력한 경우에만 기존 공통 대비 계산을 적용한다.
- 실제 배경과 선호 글씨의 대비가 4.5:1 이상이면 유지하고, 미달이면 검정·흰색 중 대비가 높은 색으로 자동 보정한다.
- 설정 미리보기, 메인 달력, 오른쪽 상세 카드가 같은 결과를 보여야 한다.
- 흰 배경+흰 글씨, 검정 배경+검정 글씨, 투명 배경 위 가변 글씨는 금지한다.

## 6. 오케스트레이터 결정 순서

1. 정보색인지 장식색인지 판단한다. 장식이면 중립색을 우선한다.
2. 정보색이면 고정 의미색을 확인하고, 아니면 현재 프리셋 배열 순서를 쓴다.
3. 스킨에 맞춰 `CategoryColorSystem`으로 배경·글씨·테두리를 계산한다.
4. 실제 배경과 글씨 대비 4.5:1 이상을 검증한다.
5. 인접 요소가 경쟁하면 채도를 높이지 말고 한쪽을 중립색으로 낮춘다.
6. 파스텔·블랙과 설정 미리보기·달력·상세 카드를 함께 확인한다.

## 7. 금지

- 화면마다 별도 HEX 또는 글씨색 계산 추가
- 대표색을 헤더·버튼·카드·아이콘에 동시에 반복
- 블랙 스킨에서 네온색과 발광 효과로 구분
- 대비 검증 없이 사용자 글씨색을 그대로 출력
- 중복 회피를 위한 난수색 또는 미세 RGB 변형
- 일반 카테고리에 근거 없이 다른 계열 글씨색을 자동 배치
# 설정 저장 원칙

- 추천 팔레트 3종은 현재 색 배치를 시작하는 템플릿일 뿐이며 프리셋 자체를 수정하지 않는다.
- 카테고리 카드에서 고른 색이 곧 사용자 설정이다. `내설정`은 설정 창을 열었을 때의 현재 배치로 돌아가는 항목이며 별도 저장 버튼은 두지 않는다. RGB, 색상 교환, 추천색 초기화 단계도 두지 않는다.
- 설정 창을 열거나 스킨을 전환하는 동작만으로 저장된 카테고리 색을 덮어쓰지 않는다.
- 승인된 버튼·스크롤 조합은 `PlannerSettings`의 새 설치 기본값으로 유지하고, 이후 사용자가 버튼 팔레트로 덮어쓸 수 있다.
- 설정 화면의 위아래 섹션은 1열 왼쪽 시작선과 2열 중간 시작선을 공통 기준으로 맞춘다. 항목 내부의 가변 문구를 억지로 고정 폭으로 만들지 않는다.
- 공휴일은 재배치 대상에서 제외하고 빨강 계열로 고정한다. 다만 프리셋에 따라 선명함과 명도는 함께 변한다.

# ONHARU 색상 조합 표준

이 문서는 ONHARU 2.2 이후의 카테고리 색상, 추천 프리셋, 스킨별 표현과 검증 기준을 정의하는 공식 디자인 기준이다. 색상 변경 시 임의 배색보다 이 문서를 우선한다.

## 1. 핵심 원칙

1. 색은 장식이 아니라 일정 출처를 구분하는 정보다.
2. ONHARU 2.1의 조화 원칙을 계승하되, 최종 기준은 블랙 스킨의 확정 원색 배열이다.
3. 프리셋 이름과 색의 인상이 일치해야 한다. 이름만 바꾸고 무관한 색을 섞지 않는다.
4. 실행할 때마다 색이 달라지는 난수 배정은 금지한다. 다양성은 검토된 고정 배열의 순서 변화로 만든다.
5. 스킨은 카테고리의 색상 정체성을 바꾸지 않고 채도·명도·글자 대비를 바꾼다.
6. 사용자가 직접 수정한 `내설정`과 Google 원본색 모드는 자동으로 덮어쓰지 않는다.
7. 사용자는 배경 기준색만 선택한다. 글자색은 공통 색상 모듈이 실제 렌더링 배경과 WCAG 명암 대비를 계산해 자동 결정한다.

## 2. 카테고리 기준색

| 역할 | 기준색 | 의미 |
|---|---:|---|
| 업무일정 | 선택 프리셋 첫 번째 색 | 프리셋의 대표색 |
| 개인일정 | 선택 프리셋 두 번째 색 | 대표색과 대비되는 보조색 |
| 야구 | `#38A169` | 모든 프리셋에서 유지하는 필드 그린 |
| D-Day | 프리셋별 | 카운트다운의 오렌지 계열을 중심으로 프리셋 분위기에 맞춤 |
| 기념일 | 프리셋별 | 로즈·마젠타·바이올렛 계열에서 프리셋 분위기에 맞춤 |
| 휴일 | `#DC2626` | 모든 프리셋의 선명한 기준 레드 |

- 야구와 휴일은 모든 추천 프리셋에서 각각 필드 그린과 선명한 레드를 유지한다.
- D-Day와 기념일은 라디오 프리셋 선택에 따라 함께 변경한다. 사용자가 직접 편집하는 것도 허용한다.

|---|---|---|
| 오션블루 | `#E67E22` | `#C2418C` |
| 핫핑크 | `#F97316` | `#DB2777` |

- 업무·개인·Google 캘린더는 프리셋 분위기에 맞게 바뀌어도 서로 즉시 구분되어야 한다.

## 3. 블랙 기준 프리셋

세 스킨은 동일한 다섯 이름과 아래 원색 배열을 사용한다. 첫 번째 색은 대표색이며, 나머지는 유사색만 반복하지 않고 대비되는 여러 계열로 구성한다.

| 프리셋 | 기준 원색 배열 |
|---|---|
| 오션블루 | `#00A6C8`, `#2859C5`, `#159E83`, `#7041C6`, `#D58A17`, `#E25555`, `#7FAE22`, `#B23BC8` |
| 핫핑크 | `#D62976`, `#315FAE`, `#168D7A`, `#D28A18`, `#7046B8`, `#6C9E2B`, `#1496B5`, `#D86A22` |
| 라임펄스 | `#86B51B`, `#3567C4`, `#793A9B`, `#D57B14`, `#168E7A`, `#C93C70`, `#158FA5`, `#D7A826` |
| 바이올렛 | `#7442C8`, `#198F83`, `#D18B18`, `#3F6FC4`, `#C93B55`, `#75A62C`, `#168FAE`, `#D56A24` |
| 시안나이트 | `#00A9C7`, `#4D55BD`, `#138F7B`, `#D18B18`, `#B944C1`, `#3266C2`, `#D35D7E`, `#6C9D2B` |

- 블랙 배경의 기준은 `#121212`이며 카드·달력 표면은 `#1A1A1A` 계열을 사용한다.
- 파스텔과 블랙은 위 배열을 별도로 재배색하지 않고 동일한 원색에서 톤을 변환한다.
- 형광에 가까운 고명도 네온색은 작은 글자의 대비와 장시간 가독성을 떨어뜨리므로 기준색에서 제외한다.

## 4. 실제 렌더링 규칙

| 스킨 | 일정 배경 | 일정 글자 | 목적 |
|---|---|---|---|
| 파스텔 | 기준색에 흰색 80% 혼합 | 같은 계열에서 4.5:1 대비를 만족하는 가장 부드러운 진한 색 | 메인 달력·설정 색상 카드·오른쪽 상세 카드의 동일한 파스텔 표현 |
| 블랙 | 선명도를 보강한 기준색 자체 | 같은 계열의 밝은 색 | 어두운 배경에서 강한 대비 |

- 설정의 색상 카드도 실제 달력과 같은 색상 관계를 미리 보여야 한다.
- 팔레트 카드만 예쁘고 달력 결과가 다른 구현은 허용하지 않는다.
- 중요한 일정처럼 의미가 별도로 정의된 상태색은 카테고리색보다 우선할 수 있다.
- 블랙에서도 녹색·노란색처럼 밝은 일정 블록은 밝은 글자를 강제하지 않고 실제 대비가 더 높은 진한 글자를 사용한다.
- 구현 기준은 단순 명도 임계값이 아니라 WCAG 상대 명도 공식의 대비율 4.5:1 이상이다. 같은 계열의 밝은색·진한색 후보를 먼저 사용하고 둘 다 부족할 때 `#111827` 또는 흰색을 검사하며, 그래도 부족하면 검정·흰색 중 대비가 높은 쪽으로 최종 보장한다.
- 설정 미리보기와 실제 달력은 모두 `App/CategoryColorSystem.cs`를 사용한다. 화면별로 별도 글자색 계산식을 만들지 않는다.

### 오른쪽 상세 카드

- 파스텔의 설정 색상 카드와 오른쪽 일반 일정·D-Day·기념일·야구 카드는 메인과 동일하게 흰색 80% 혼합 배경과 자동 계산한 동계열 글자를 사용한다.
- 오른쪽 상세 카드 배경과 글자는 달력 일정 막대의 계산 결과를 그대로 사용한다. 별도의 상세 카드 보정값을 두지 않는다.
- 체크박스는 상태를 즉시 구분해야 하는 조작 요소이므로 파스텔 카드보다 한 단계 진하게 표시한다. 파스텔 스킨은 기준색에 흰색 58%를 혼합하고, 블랙 스킨은 선명한 기준색을 사용한다.
- 블랙의 달력 일정·설정 색상 카드·오른쪽 상세 카드는 모두 흰색 글자를 사용한다. 밝은 기준색은 색조를 유지한 채 배경만 자동으로 어둡게 하여 흰 글자 대비율 4.5:1 이상을 보장한다.
- 블랙 설정 색상 카드 오른쪽의 작은 칩은 원색을 반복하지 않고 해당 기준색의 파스텔 변환 결과를 보여준다.
- 프리셋 라디오는 동일 폭으로 배치하며, 색상 편집 카드의 체크박스·제목·미리보기 칩은 수직 중앙에 정렬한다.
- 오른쪽 선택 날짜·이번 주·다음 주 탭은 미선택 시 중립 배경·회색 글자, 선택 시 강한 인디고 배경·흰색 글자를 사용한다. 중요한 날 버튼은 별도 의미 규칙을 유지한다. 미설정은 연회색 `#F1F5F9` 배경·`#475569` 글자·`#94A3B8` 테두리, 설정됨은 사용자가 고른 색에 흰색 58%를 혼합한 강한 파스텔 배경·진분홍 `#BE185D` 글자·`#F472B6` 테두리를 사용한다.
- 블랙의 오른쪽 상세 카드와 설정 색상 카드는 같은 기준색 배경과 흰 글자를 사용한다. 오른쪽 카드만 별도로 색을 어둡히거나 바꾸지 않는다.
- 블랙의 `선택 날짜·이번 주·다음 주·중요한 날`은 같은 보라 계열 상태색을 사용하고, 선택 상태만 진한 면과 흰 글자로 표시한다.
- 카드의 기준색은 업무·개인·Google·야구·D-Day·기념일에 저장된 사용자 설정색을 사용한다.
- 카드 제목과 본문은 스킨 공통 글자색을 가져오지 않는다. 기준색을 단계적으로 어둡게 하면서 대비율 4.5:1을 처음 만족하는 색을 선택하고, 불가능할 때만 안전한 검정·흰색으로 대체한다.
- 블랙 스킨에서도 오른쪽 카드만 갑자기 어두워지거나 흰 글자로 전환되지 않는다.
- 모든 스킨의 체크박스는 각 카테고리 기준색 면과 흰 체크 표시를 사용해 선택 여부를 즉시 구분한다. 블랙의 라벨은 체크 면의 자동 대비색을 재사용하지 않고 밝은 스킨 공통 글자색을 사용한다.
- 블랙 스킨의 선택 날짜와 오른쪽 `중요한 날` 버튼은 사용자 선택색을 중간 명도로 보정해 어두운 달력에서 묻히지 않게 한다.

## 5. 중복과 유사색 판정

1. 같은 프리셋 안에서 동일한 HEX 값은 허용하지 않는다.
2. 업무와 첫 번째 Google 캘린더처럼 화면에서 자주 나란히 보이는 항목은 밝기만 다른 같은 계열을 배정하지 않는다.
3. 자동 생성되는 Google 추가색은 현재 로컬·Special Day·앞선 Google 색과 충돌하면 다른 후보색으로 교체한다.
4. 자동 검사는 정확한 HEX 중복을 막고, 육안 검사는 다음을 확인한다.
   - 작은 일정 막대에서도 구분되는가
   - 파스텔에서 모두 회색처럼 뭉개지지 않는가
   - 블랙에서 두 네온색이 같은 색처럼 보이지 않는가
   - 색각 이상 사용자가 색 외에도 카테고리명으로 구분할 수 있는가

## 6. 변경 절차

1. 이 문서의 블랙 기준 원색 배열과 현재 화면을 먼저 비교한다.
2. 기존 의미색을 유지할 수 있는지 확인한다.
3. 프리셋 이름에 맞는 조합인지 검토한다.
4. 파스텔·블랙 두 화면과 설정 색상 카드를 함께 확인한다.
5. 실제 Google 캘린더가 연결된 상태에서 업무·개인과 유사하지 않은지 확인한다.
6. `theme-check.ps1`과 전체 `check-v22.ps1`을 통과한다.
7. 변경 이유와 사용자 확인 결과를 `HANDOFF.md`에 기록한다.

## 7. 금지 사항

- 프리셋 이름과 무관한 난수색 배정
- 중복을 피하려고 RGB 값만 미세하게 바꾸는 처리
- Special Day 의미색을 프리셋마다 전혀 다른 계열로 변경
- 설정창의 미리보기만 변경하고 실제 일정 렌더링은 그대로 두는 처리
- 이 문서와 사용자 승인 없이 기준 원색 배열 전체를 교체하는 작업

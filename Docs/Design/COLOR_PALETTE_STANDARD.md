# ONHARU 색상 조합 표준

이 문서는 ONHARU 2.2 이후의 카테고리 색상, 추천 프리셋, 스킨별 표현과 검증 기준을 정의하는 공식 디자인 기준이다. 색상 변경 시 임의 배색보다 이 문서를 우선한다.

## 1. 핵심 원칙

1. 색은 장식이 아니라 일정 출처를 구분하는 정보다.
2. ONHARU 2.1의 조화 원칙을 계승하되, 파스텔은 밝고 맑은 결과를 최우선으로 한다.
3. 프리셋은 단일 대표색 계열이 아니라 분위기와 톤이 다른 혼합 색상 조합이다.
4. 시작 무작위 배치는 사용자 옵션이 켜진 경우에만 허용한다. 옵션이 꺼지면 마지막 저장 배열을 유지한다.
5. 스킨은 카테고리의 색상 정체성을 바꾸지 않고 채도·명도·글자 대비를 바꾼다.
6. 사용자가 직접 수정한 `내설정`과 Google 원본색 모드는 자동으로 덮어쓰지 않는다.
7. 추천 프리셋은 배경·글씨를 한 쌍으로 저장한다. 팔레트 작성 시 WCAG 4.5:1을 검증하고, 실행 중에는 선택한 HEX를 바꾸지 않는다.

## 2. 카테고리 기준색

| 역할 | 기준색 | 의미 |
|---|---:|---|
| 업무일정 | 선택 프리셋 첫 번째 색 | 첫 번째 카테고리 구분색 |
| 개인일정 | 선택 프리셋 두 번째 색 | 첫 번째 색과 다른 계열의 구분색 |
| 야구 | 선택 프리셋 세 번째 색 | 저장된 카테고리 구분색 |
| D-Day | 선택 프리셋 네 번째 색 | 저장된 카테고리 구분색 |
| 기념일 | 선택 프리셋 다섯 번째 색 | 저장된 카테고리 구분색 |
| 휴일 | 선택 프리셋 여섯 번째 색 | 저장된 카테고리 구분색 |

- 여섯 로컬 역할과 최대 여섯 Google 역할은 선택 조합의 서로 다른 12색을 사용한다.
- 무작위 옵션을 켜면 역할과 색의 연결만 섞고 12색 조합 자체는 바꾸지 않는다.

## 3. 고정 추천 조합

두 스킨은 동일한 세 조합과 아래 글씨색 배열을 사용한다. 이름은 특정 색이 아니라 조합의 밝기·생동감·분위기를 뜻한다.

| 프리셋 | 기준 원색 배열 |
|---|---|
| 맑고 선명한 조합 | `#1D4ED8`, `#BE185D`, `#087A4B`, `#806000`, `#6D28D9`, `#C62828`, `#0F766E`, `#4338CA`, `#C2410C`, `#0E7490`, `#4D7C0F`, `#A21CAF` |
| 차분한 중간톤 | `#3F5F85`, `#884B60`, `#35684B`, `#705A18`, `#674F80`, `#9F3F46`, `#356763`, `#505584`, `#8F4B28`, `#346575`, `#536C28`, `#7B496F` |
| 밝고 산뜻한 조합 | `#3457A4`, `#A92E5C`, `#16704B`, `#755C00`, `#70429B`, `#B4234D`, `#146D67`, `#4F4AA3`, `#A84616`, `#176C82`, `#4F7812`, `#943782` |

- 블랙 배경의 기준은 `#121212`이며 카드·달력 표면은 `#1A1A1A` 계열을 사용한다. 추천 프리셋은 이미 확정된 글씨색을 기준으로 어둡히며 `Vivid` 채도 증폭을 다시 적용하지 않는다.
- 파스텔과 블랙은 위 배열을 별도로 재배색하지 않고 동일한 원색에서 톤을 변환한다.
- 형광에 가까운 고명도 네온색은 작은 글자의 대비와 장시간 가독성을 떨어뜨리므로 기준색에서 제외한다.
- 파스텔 추천 조합은 낮은 명도로 어둡거나 탁하게 보이는 결과를 허용하지 않는다.
- 세 조합의 36개 배경·글씨 쌍은 `OnharuColorPresets`에 함께 저장한다. 모두 작성 단계에서 4.5:1 이상을 통과했으며 설정 미리보기·달력·오른쪽 카드는 해당 HEX를 1:1로 사용한다.
- 배열 앞 여섯 칸은 대중적인 일정 앱의 의미 관습에 맞춰 `업무=블루`, `개인=로즈`, `야구=그린`, `D-Day=골드`, `기념일=바이올렛`, `휴일=레드` 순서를 유지한다. Google 여섯 칸은 남은 계열을 분산해 서로 구분한다.

## 4. 실제 렌더링 규칙

| 스킨 | 일정 배경 | 일정 글자 | 목적 |
|---|---|---|---|
| 파스텔 | 프리셋에 확정된 옅은 배경 HEX | 프리셋에 확정된 동계열 글씨 HEX | 메인 달력·설정 색상 카드·오른쪽 상세 카드의 1:1 표현 |
| 블랙 | 선명도를 보강한 기준색 자체 | 같은 계열의 밝은 색 | 어두운 배경에서 강한 대비 |

- 설정의 색상 카드도 실제 달력과 같은 색상 관계를 미리 보여야 한다.
- 스크롤바는 카테고리색과 분리하되 화면에서 살짝만 인식되는 옅은 인터페이스 색을 사용한다. 파스텔 상세 손잡이는 라벤더 `#B7ACE8`, 트랙은 `#F1F5F9`, 블랙 손잡이는 기존 `#8C8C96`을 사용한다.
- 팔레트 카드만 예쁘고 달력 결과가 다른 구현은 허용하지 않는다.
- 중요한 일정처럼 의미가 별도로 정의된 상태색은 카테고리색보다 우선할 수 있다.
- 블랙에서도 녹색·노란색처럼 밝은 일정 블록은 밝은 글자를 강제하지 않고 실제 대비가 더 높은 진한 글자를 사용한다.
- 구현 기준은 단순 명도 임계값이 아니라 WCAG 상대 명도 공식의 대비율 4.5:1 이상이다. 같은 계열의 밝은색·진한색 후보를 먼저 사용하고 둘 다 부족할 때 `#111827` 또는 흰색을 검사하며, 그래도 부족하면 검정·흰색 중 대비가 높은 쪽으로 최종 보장한다.
- 설정 미리보기와 실제 달력은 모두 `App/CategoryColorSystem.cs`를 사용한다. 화면별로 별도 글자색 계산식을 만들지 않는다.

### 오른쪽 상세 카드

- 파스텔의 설정 색상 카드와 오른쪽 일반 일정·D-Day·기념일·야구 카드는 메인과 동일하게 흰색 80% 혼합 배경과 자동 계산한 동계열 글자를 사용한다.
- 오른쪽 상세 카드 배경과 글자는 달력 일정 막대의 계산 결과를 그대로 사용한다. 별도의 상세 카드 보정값을 두지 않는다.
- 오른쪽 필터와 상세 일정의 체크박스는 선택 프리셋과 관계없이 같은 역할 열의 `맑고 선명한 조합`을 사용한다. 왼쪽 달력 일정과 카드 배경은 선택 프리셋을 유지한다.
- 오른쪽 기간 선택 버튼은 선명한 오렌지, 정렬 선택 버튼은 선명한 블루를 고정 강조색으로 사용하며 미선택 상태는 중립색을 유지한다.
- 체크박스는 상태를 즉시 구분해야 하는 조작 요소이므로 파스텔 카드보다 한 단계 진하게 표시한다. 파스텔 스킨은 기준색에 흰색 58%를 혼합하고, 블랙 스킨은 선명한 기준색을 사용한다.
- 파스텔 체크박스는 같은 색조를 유지하고 카드보다 선명하게 하되 어두운 면으로 만들지 않는다.
- 옅은 핑크+핫핑크 글씨처럼 같은 계열 조합은 일반 카테고리의 기본 규칙이다. 옅은 노랑+파란 글씨 같은 교차 계열 조합은 사용자가 명시적으로 선택하는 중요 일정 강조 팔레트에서만 허용한다.
- 블랙의 달력 일정·설정 색상 카드·오른쪽 상세 카드는 모두 흰색 글자를 사용한다. 밝은 기준색은 색조를 유지한 채 배경만 자동으로 어둡게 하여 흰 글자 대비율 4.5:1 이상을 보장한다. 사용자 지정 중요 일정 글씨는 선호색의 대비가 충분할 때만 유지하고 부족하면 자동 보정한다.
- 블랙 설정 색상 카드 오른쪽의 작은 칩은 원색을 반복하지 않고 해당 기준색의 파스텔 변환 결과를 보여준다.
- 프리셋 라디오는 동일 폭으로 배치하며, 색상 편집 카드의 체크박스·제목·미리보기 칩은 수직 중앙에 정렬한다.
- 오른쪽 선택 날짜·이번 주·다음 주 탭은 미선택 시 중립 배경·회색 글자, 선택 시 강한 인디고 배경·흰색 글자를 사용한다. 중요한 날 버튼은 별도 의미 규칙을 유지한다. 미설정은 연회색 `#F1F5F9` 배경·`#475569` 글자·`#94A3B8` 테두리, 설정됨은 사용자가 고른 색에 흰색 58%를 혼합한 강한 파스텔 배경·진분홍 `#BE185D` 글자·`#F472B6` 테두리를 사용한다.
- 블랙의 오른쪽 상세 카드와 설정 색상 카드는 같은 기준색 배경과 흰 글자를 사용한다. 오른쪽 카드만 별도로 색을 어둡히거나 바꾸지 않는다.
- 블랙의 `선택 날짜·이번 주·다음 주·중요한 날`은 같은 보라 계열 상태색을 사용하고, 선택 상태만 진한 면과 흰 글자로 표시한다.
- 카드의 기준색은 업무·개인·Google·야구·D-Day·기념일에 저장된 사용자 설정색을 사용한다.
- 카드 제목과 본문은 스킨 공통 글자색을 가져오지 않는다. 기준색을 단계적으로 어둡게 하면서 대비율 4.5:1을 처음 만족하는 색을 선택하고, 불가능할 때만 안전한 검정·흰색으로 대체한다.
- 블랙 스킨에서도 오른쪽 카드만 갑자기 어두워지거나 흰 글자로 전환되지 않는다.
- 모든 스킨의 체크박스는 각 카테고리 기준색 면과 흰 체크 표시를 사용해 선택 여부를 즉시 구분한다. 블랙의 라벨은 체크 면의 자동 대비색을 재사용하지 않고 밝은 스킨 공통 글자색을 사용한다.
- 블랙 스킨의 선택 날짜와 오른쪽 `중요한 날` 버튼은 사용자 선택색을 중간 명도로 보정해 어두운 달력에서 묻히지 않게 한다.

## 5. 중복과 유사색 판정

1. 같은 프리셋 안에서 동일한 HEX 값은 허용하지 않는다.
2. 업무와 첫 번째 Google 캘린더처럼 화면에서 자주 나란히 보이는 항목은 밝기만 다른 같은 계열을 배정하지 않는다.
3. 자동 생성되는 Google 추가색은 현재 로컬·Special Day·앞선 Google 색과 충돌하면 다른 후보색으로 교체한다.
4. 자동 검사는 정확한 HEX 중복을 막고, 육안 검사는 다음을 확인한다.
   - 작은 일정 막대에서도 구분되는가
   - 파스텔에서 모두 회색처럼 뭉개지지 않는가
   - 블랙에서 두 네온색이 같은 색처럼 보이지 않는가
   - 색각 이상 사용자가 색 외에도 카테고리명으로 구분할 수 있는가

## 6. 변경 절차

1. 이 문서의 블랙 기준 원색 배열과 현재 화면을 먼저 비교한다.
2. 기존 의미색을 유지할 수 있는지 확인한다.
3. 프리셋 이름에 맞는 조합인지 검토한다.
4. 파스텔·블랙 두 화면과 설정 색상 카드를 함께 확인한다.
5. 실제 Google 캘린더가 연결된 상태에서 업무·개인과 유사하지 않은지 확인한다.
6. `theme-check.ps1`과 전체 `check-v22.ps1`을 통과한다.
7. 변경 이유와 사용자 확인 결과를 `HANDOFF.md`에 기록한다.

## 7. 금지 사항

- 프리셋 이름과 무관한 난수색 배정
- 중복을 피하려고 RGB 값만 미세하게 바꾸는 처리
- Special Day 의미색을 프리셋마다 전혀 다른 계열로 변경
- 설정창의 미리보기만 변경하고 실제 일정 렌더링은 그대로 두는 처리
- 이 문서와 사용자 승인 없이 기준 원색 배열 전체를 교체하는 작업

## 8. 팝업 톤 기준

- 메인 달력과 오른쪽 상세 패널의 현재 파스텔 색상은 제품의 기준 화면으로 고정한다.
- 팝업은 중립 쿨그레이 `#F7F7FA` 바탕과 중간톤 회청색 `#AEB4C0` 외곽선으로 메인 화면과 분리한다. 블랙 테마에서도 팝업은 같은 밝은 작업면을 사용한다.
- 팝업 내부는 흰 내용 카드 `#FFFFFF`, 중립 보조 카드 `#F2F4F7`를 공통으로 사용한다.
- 모든 팝업 헤더는 슬레이트 `#E9EDF3`, 제목은 `#334155`로 통일한다. 기능 고유색을 헤더 전체나 제목 글자에 반복하지 않는다.
- 주요 실행은 옅은 블루 `#DBEAFE`·파랑 글자 `#1D4ED8`·테두리 `#93C5FD`를 사용한다.
- 탭·분할 선택은 블루그레이 `#DCE7F6`·슬레이트 글자 `#334155`·테두리 `#9FB1C7`를 사용한다.
- 일반 조작은 슬레이트 `#F1F5F9`·`#475569`·`#CBD5E1`, 완료·연결은 민트, 주의는 오렌지, 삭제·오류는 코랄 계열을 사용한다.
- 넓은 면적에 진한 브랜드색을 사용하지 않는다. 진한 색은 글자와 작은 아이콘에 제한한다.
